## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn — **already initialized** during Phase 1 execution (`components.json` present, style `radix-nova`, baseColor `neutral`). No re-init needed. |
| Preset | `radix-nova` / neutral base / dark theme default, `cssVariables: true`, prefix none. Matches `D:/Github/dxf-demo/components.json` on disk. |
| Component library | Radix primitives via shadcn. Installed already: Button, Badge, ScrollArea, Tooltip, Separator. **New for Phase 2:** AlertDialog (batch-delete confirmation), Sonner/`toast` (export success + validation-failure feedback). Both are shadcn official registry components — install via `npx shadcn add alert-dialog sonner` before/at the start of implementation. No pre-built third-party "properties panel" or "toolbar" block is used — both are hand-built compositions of the primitives above, consistent with Phase 1's approach. |
| Icon library | lucide-react (unchanged). New icons for Phase 2: `Trash2` (Delete), `Undo2` / `Redo2` (undo/redo), `Download` (Export DXF). Reused from Phase 1: `Eye`/`EyeOff` (hide/show, applied at entity level now in addition to layer level), `AlertTriangle` (destructive-confirmation dialog icon, same pattern as Phase 1's unknown-entity warning). |
| Font | Inter (unchanged), no monospace requirement added — coordinate/geometry values in the properties panel render in the existing body font, not a mono face. |

**Layout extension (Phase 2 adds a toolbar row and a third sidebar section):**

- App grid changes from `[320px_1fr] / [48px_1fr]` (Phase 1) to `[320px_1fr] / [48px_48px_1fr]` — header (48px, unchanged) stays full-width; a new **Cleanup Toolbar** row (48px, matches the `2xl` spacing token) sits directly below the header, spanning only the canvas column (not the sidebar); the sidebar spans both the toolbar row and the canvas row so it reads as one continuous panel.
- Sidebar becomes three stacked sections instead of Phase 1's two: **Layer Panel** (fixed height, reduced from Phase 1's 300px to **240px** to make room), **Separator**, **Structure Browser** (`flex-1`, unchanged sizing behavior), **Separator**, **Properties Panel** (new, fixed height **220px**). This is a deliberate modification to Phase 1's `App.tsx` sidebar layout, not an additive change — flag it as such in the plan.
- Properties Panel is **always mounted** (never conditionally removed) and shows its empty-state copy when there is no selection, matching the established Phase 1 pattern of always-visible panels with empty states (never a panel that appears/disappears based on state, which would cause layout jank).

## Spacing Scale

Declared values (must be multiples of 4) — **unchanged from Phase 1**, extended with new usage:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, swatch-to-name gap (unchanged); gap between selection-count badge and toolbar buttons |
| sm | 8px | Compact spacing: tree indent step, badge padding (unchanged); properties panel field-label-to-value gap |
| md | 16px | Default spacing: panel section padding, row internal padding (unchanged); toolbar horizontal padding |
| lg | 24px | Section padding (unchanged) |
| xl | 32px | Layout gaps; toolbar icon-button hit target — Delete/Hide/Undo/Redo buttons use the same 32px square target as Phase 1's zoom controls |
| 2xl | 48px | Major section breaks (unchanged) — **new usage:** Cleanup Toolbar row height, matching the existing header height |
| 3xl | 64px | Page-level spacing (unchanged) |

Exceptions:
- Layer Panel fixed height: **240px** (reduced from Phase 1's 300px — see Layout note above).
- Properties Panel fixed height: **220px** (new).
- Batch-delete confirmation threshold: exactly **10 entities** (CONTEXT.md decision) — 1-9 entity deletes proceed with no dialog; 10+ triggers the AlertDialog.
- Rubber-band selection box: 1px accent (`#3B82F6`) border, accent fill at 10% opacity — not a spacing token, but declared here since it's a new drag-interaction visual with no other natural home in this template.

## Color

**Unchanged tokens from Phase 1** — this phase does not introduce new hex values, only new usage assignments within the existing 60/30/10 contract. Canvas-rendered DXF entity colors remain the file's own resolved BYLAYER/BYBLOCK colors, rendered as-is (Phase 1 scope note carries forward unchanged).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#1E1E1E` | Canvas viewport background, app shell background (unchanged) |
| Secondary (30%) | `#2A2A2E` | Sidebar/toolbar surface, row hover background (unchanged); Cleanup Toolbar row background; Properties Panel surface |
| Accent (10%) | `#3B82F6` | **New:** selection outline/stroke on every selected entity on canvas (extends Phase 1's single-entity hover/selection highlight to multi-select — all selected entities get the same outline simultaneously); rubber-band selection box border + 10%-opacity fill; selection-count badge background; primary "Export DXF" button. Existing uses (Load DXF button, hover highlight, focus rings) carry forward unchanged. |
| Destructive | `#EF4444` | **New:** "Delete" toolbar button (icon + label, destructive button variant); batch-delete AlertDialog heading icon (`AlertTriangle`) and primary "Delete {N} entities" confirm button. Existing use (unknown-entity warning banner) carries forward unchanged. |

Accent reserved for: everything listed above plus the Phase 1 list (primary CTA, canvas hover/selection highlight, active structure-browser row, focus-visible outlines). Never used for static chrome.

**Hide is not destructive-colored.** The "Hide" toolbar button uses the neutral/outline button variant (same visual weight as Phase 1's "Show All"/"Hide All" layer buttons) — hiding is reversible view-only state (CONTEXT.md decision: hidden entities remain in export), so it must not read as dangerous the way Delete does.

**Hidden-entity canvas rendering is not a UI-chrome color.** A hidden entity renders in its own resolved DXF layer color (PARSE-02) at 20% opacity with a dashed stroke (CONTEXT.md decision) — never remapped to a special UI-chrome hex value. This keeps the 60/30/10 contract scoped to chrome only, per the Phase 1 scope note.

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5) and lifted by plan-phase's
> `## UI Considerations` lift rule via the identical rule as SPEC `## Edge Coverage`. Shape-rooted UI *state*
> coverage (empty / loading / error / populated / partial / overflow / zero-one-many / long-text).
> Empty-state and error-state COPY live in `## Copywriting Contract` above — this section covers
> state coverage and REFERENCES those rows rather than restating the copy (de-dup).

Elements classified: Properties Panel (`list-collection`), Cleanup Toolbar / Export DXF flow (`interactive-control`), Selection-count badge (`static-content`), Canvas viewer selection highlight (`media`/`interactive-control`, extends Phase 1's classification), Box-select rubber band (`interactive-control`), Batch-delete AlertDialog (`interactive-control`).

Applicable state considerations resolved: 8 covered, 1 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Properties Panel | ✅ covered | Zero selection shows the dedicated empty-state copy (see Copywriting Contract "Properties panel empty state") instead of a blank or hidden panel — panel stays mounted at all times |
| populated | Properties Panel | ✅ covered | Single-entity selection shows the full field set (Type, Layer, Color, key geometry); multi-entity selection (2+) shows the count + per-type breakdown summary instead of stacking N full detail blocks (CONTEXT.md decision) |
| partial | Properties Panel | 🧪 backstop | An entity missing an optional geometry field (e.g. a TEXT entity with no rotation angle) renders that field row as "—" rather than omitting the row — verified via a sparse-attribute fixture entity |
| overflow / long-text | Properties Panel | ✅ covered | Long field values (long TEXT/MTEXT content, high-precision coordinates) truncate with ellipsis at the 320px panel width; full value via tooltip on hover — same truncation pattern as Phase 1's layer/entity name handling |
| zero-one-many | Properties Panel | ✅ covered | Zero → empty-state copy; one → full single-entity detail view; many → "{N} entities selected" summary with type breakdown, never a stacked list of N full detail blocks |
| loading | Export DXF flow | ✅ covered | Button shows "Exporting…" and disables during in-memory generate + re-parse validation (EXPORT-02); no separate spinner/overlay — the surgical filter (not a full regenerate) completes well under a second even on large files |
| error | Export DXF flow | ✅ covered | A validation failure (re-parsed entity count mismatch) blocks the save entirely — shows the export validation-failure toast (see Copywriting Contract) and no file is written; user can retry or narrow their selection |
| overflow | Selection-count badge | ✅ covered | Badge renders the exact integer count in a fixed-width numeric style; no truncation needed at any realistic entity-selection volume |
| populated | Canvas viewer (multi-select extension) | ✅ covered | Extends Phase 1's single-entity accent outline to render the same accent outline on every currently-selected entity simultaneously, not just the most recently clicked one |
