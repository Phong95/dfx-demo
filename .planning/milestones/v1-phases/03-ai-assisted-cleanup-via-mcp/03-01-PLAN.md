## Phase Goal

**As a** civil engineer, **I want to** describe cleanup intent in natural language to Claude Desktop, **so that** AI can inspect my loaded drawing and propose or apply cleanup operations safely without risking unreviewed destructive changes.

<objective>
Establish the two-process MCP server architecture and prove it end-to-end with the `list_layers` tool. After this plan, the Engine Server (started by `npm run dev`) hosts the document model over WebSocket, and a separate MCP relay process (spawned by Claude Desktop) bridges stdio JSON-RPC tool calls to the engine -- proving the architecture from the MCP SDK through the WS relay to real DXF data and back. Covers MCP-01 partially (1 of 6 tools).

Purpose: Prove the hardest architectural risk first -- the two-process relay pattern (RESEARCH Pattern 1) that reconciles Claude Desktop's stdio requirement with the browser-facing dev server. Every subsequent tool is an expansion of this proven path.

Output: Engine server, MCP relay, list_layers tool, server TypeScript/ESLint configs, concurrently-based dev script.
</objective>

Create src/server/wsProtocol.ts defining typed message interfaces for the WS protocol. Define a discriminated union on a type field. Message types needed for this tracer: sync_state (browser sends rawFileText + fileName + deletedEntityIndices + hiddenEntityIndices + version to engine), tool_request (relay sends tool name + params + a requestId), tool_response (engine replies with result + requestId + optional error). Keep the type definitions minimal — only what this plan needs; Plan 02 adds apply_mutation messages.

Create src/server/documentModel.ts as the server-side document mirror. It imports DxfParser from dxf-parser, rawTagScan from @/dxf/rawTagScan, and resolveAllColors from @/dxf/resolveColors (all verified Node-safe in RESEARCH.md). Expose a DocumentModel class or plain object with: load(rawFileText, fileName) that parses via new DxfParser().parseSync(), runs rawTagScan(), runs resolveAllColors(), and stores dxfData + unknownEntityReport + layerFlags; updateState(deletedEntityIndices, hiddenEntityIndices, version) to mirror browser mutation state; getLayerInfo() that iterates dxfData.tables.layer.layers and for each layer returns name, color (hex from aciColorIndex), entity count (count entities on that layer excluding deleted indices), frozen/locked state from layerFlags. Wrap parseSync and rawTagScan in try/catch — a parse failure sets an error field, never crashes the process (RESEARCH Security Domain, Pitfall 5 malformed input).

Create src/server/engine.ts as the Engine Server. Import ws (WebSocketServer). Bind to host 127.0.0.1 on port from ENGINE_PORT env var or default 4000 (RESEARCH Security Domain: never 0.0.0.0). Implement verifyClient that checks the request origin header — accept connections from origins matching localhost/127.0.0.1 on any port (covers Vite dev server) and accept connections with no origin (covers the MCP relay WS client which is a plain Node client, not a browser). Log ready message to stderr (never stdout). On connection, identify the client role by an initial handshake message: browser clients send a sync_state message, relay clients send tool_request messages. Hold a single activeDocumentModel instance. On sync_state from browser: call documentModel.load() with the received rawFileText/fileName, then updateState() with deletion/hiding indices. On tool_request from relay: dispatch by tool name to the appropriate handler (for now only list_layers), call documentModel.getLayerInfo(), send tool_response back with the result. If documentModel has no loaded drawing, return an error response with text "No drawing loaded. Please load a DXF file in the viewer first." Handle ECONNREFUSED gracefully — if the WS server fails to bind, log the error to stderr and exit with code 1.

Create src/server/tools/listLayers.ts exporting a handleListLayers function that takes the documentModel and returns the layer info array. Each entry: name (string), color (hex string), entityCount (number, excluding deleted), frozen (boolean), locked (boolean). This is a pure function called by engine.ts when dispatching a list_layers tool_request.

Create src/server/index.ts as the MCP relay entry point. Import McpServer from @modelcontextprotocol/sdk/server/mcp.js and StdioServerTransport from @modelcontextprotocol/sdk/server/stdio.js. Import WebSocket from ws (the client class). Import z from zod for tool schemas. On startup, open a WS connection to ws://127.0.0.1:{ENGINE_PORT env var or 4000}. If connection fails (ECONNREFUSED), every tool handler returns isError true with text "Cannot reach the DXF Demo engine server. Make sure npm run dev is running, then try again." (RESEARCH Pattern 1 failure mode). Create a McpServer with name dxf-demo version 0.1.0. Register the list_layers tool with description "List all layers in the currently loaded DXF drawing with color, entity count, and frozen/locked state", empty inputSchema (zero-argument tool). The handler sends a tool_request message over the WS connection with tool name list_layers, awaits the tool_response, and returns it as a CallToolResult with content type text containing JSON-stringified layer data. Use a Map of pending requestIds to resolve promises for the request/response pairing. Connect the McpServer to a new StdioServerTransport. Catch top-level errors with console.error (stderr, never stdout — RESEARCH Pitfall 1). Ban all console.log and console.info usage in this file and everything it imports.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Claude Desktop (stdio) to MCP relay | JSON-RPC framing over stdin/stdout; controlled by Claude Desktop |
| MCP relay (WS client) to Engine Server | localhost WS; relay is trusted (same machine, same user) |
| Browser (WS client) to Engine Server | localhost WS; potentially spoofable by other browser tabs |
