Create src/server/proposals.ts implementing the in-memory proposal store per RESEARCH Pattern 3. Define the Proposal interface with fields: id (string, crypto.randomUUID), action (delete or hide), indices (number array), createdAtVersion (number, snapshot of documentModel.version at preview time), createdAt (number, Date.now), source (apply_cleanup_rule or remove_selection). Export a proposals Map and three functions: createProposal(action, indices, source, currentVersion) that creates and stores a Proposal, getProposal(id) that retrieves by id, consumeProposal(id) that deletes the entry (one-shot: confirmed or rejected proposals cannot be re-confirmed).

Create src/server/tools/applyCleanupRule.ts exporting handleApplyCleanupRule. It takes the documentModel and filter params (layer optional string, entityType optional string). It calls a resolveFilterIndices helper that iterates documentModel.dxfData.entities, skips already-deleted indices, matches on filter.layer (if provided, entity.layer must match) and filter.entityType (if provided, entity.type must match), and returns matching index numbers. If zero indices match, return a success result with text stating 0 entities match the filter (not an error). Otherwise call createProposal with the indices and return a preview: proposal_id, action, matchCount, affected entity types and layers as a readable summary string for Claude to present to the user.

Create src/server/tools/removeSelection.ts exporting handleRemoveSelection. It takes the documentModel, an array of entity indices, and an action (delete or hide). Validate each index: must be a non-negative integer, must be within bounds of dxfData.entities.length, must not already be in deletedEntityIndices. Filter out invalid indices and report them. If no valid indices remain, return an error. Call createProposal with the valid indices and return the same preview shape as applyCleanupRule: proposal_id, action, validCount, invalidCount, summary.

Create src/server/tools/confirmProposal.ts exporting handleConfirmProposal per RESEARCH Pattern 4. Retrieve the proposal via getProposal. If not found, return an error: no pending proposal with that id, it may have already been applied, rejected, or expired. Check createdAtVersion against documentModel.version. If they differ, consumeProposal (one-shot) and return an error: drawing has changed since this proposal was created, request a new preview. If version matches, consumeProposal, apply the mutation to documentModel (add indices to deletedEntityIndices or hiddenEntityIndices, increment version), then push an apply_mutation WS message to the connected browser client with the indices and action. Return success with the count of affected entities.

Create src/server/tools/exportDxf.ts exporting handleExportDxf. It takes the documentModel and a filePath string. Validate: if documentModel has no loaded drawing, return the standard no-drawing-loaded error. Validate filePath: resolve to absolute path via path.resolve, reject if it does not end in .dxf (case-insensitive), reject if the normalized path contains .. segments after resolution. Import buildEntityTagRanges from @/dxf/entityTagRanges and filterDxfText, validateExport from @/dxf/exportDxf (the pure functions only, NOT saveDxf). Build entity ranges from documentModel.rawFileText and documentModel.dxfData. Call filterDxfText with the ranges and documentModel.deletedEntityIndices. Compute expectedCount as dxfData.entities.length minus deletedEntityIndices size. Call validateExport — if it fails, return an error: export validation failed, no file written. If validation passes, call fs.writeFile (from node:fs/promises) with the filtered text. Return success with the output path and entity count.

Register all four tools in src/server/index.ts following the established pattern. Tool schemas using zod:
- apply_cleanup_rule: inputSchema with action as z.enum(['delete', 'hide']), filter as z.object({ layer: z.string().optional(), entityType: z.string().optional() })
- remove_selection: inputSchema with indices as z.array(z.number().int().nonneg()).max(50000), action as z.enum(['delete', 'hide'])
- confirm_proposal: inputSchema with proposalId as z.string()
- export_dxf: inputSchema with filePath as z.string()

Each tool handler sends a tool_request over the WS connection to the engine, awaits the tool_response, and returns the result as a CallToolResult.

Extend engine.ts tool_request dispatch to handle the four new tool names. For confirm_proposal, after applying the mutation to the document model, send an apply_mutation message to the active browser WS connection (if connected). Track the browser connection separately from relay connections so the engine knows which client to push mutations to.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Claude Desktop to MCP relay (stdio) | LLM-controlled tool inputs cross here; Zod validates shape but content (filePath, filter values) is untrusted |
| MCP relay to Engine Server (WS) | Trusted same-machine relay; but tool params originate from the LLM |
| Engine Server to filesystem | export_dxf writes to an LLM-controlled file path |
| Engine Server to browser (WS) | apply_mutation pushes indices that modify the browser store |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-02 | Tampering | export_dxf filePath | medium | mitigate | Validate path ends in .dxf (case-insensitive); resolve to absolute, reject if normalized path contains .. segments; never silently overwrite without the path being explicit in the tool call |
| T-03-03 | DoS | remove_selection indices array | low | mitigate | Zod schema bounds: z.array(z.number().int().nonneg()).max(50000) |
| T-03-06 | Info Disclosure | apply_cleanup_rule empty filter | low | accept | An empty filter (no layer, no entityType) would match ALL entities; this is valid behavior (user asked to "delete everything"), and the two-step confirm prevents accidental application. Accepted: the preview step makes the scope explicit before any action. |
| T-03-07 | Tampering | confirm_proposal stale version | medium | mitigate | createdAtVersion check against documentModel.version; stale proposals rejected with clear error message, proposal consumed (RESEARCH Pattern 4) |
</threat_model>
