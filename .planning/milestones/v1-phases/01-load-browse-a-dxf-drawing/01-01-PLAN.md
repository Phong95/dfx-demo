<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user-file to parser | Untrusted DXF file content from the user's filesystem crosses into the dxf-parser and raw-tag scanner in the Web Worker |
| worker to main-thread | Parsed data from the Web Worker crosses into the main thread zustand store via postMessage |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Denial of Service | dxf-parser.parseSync() and rawTagScan() in Web Worker | medium | mitigate | Wrap both calls in try/catch inside dxf.worker.ts; on any exception postMessage a structured error object back to main thread; never let an unhandled throw propagate from the worker |
| T-01-02 | Denial of Service | Web Worker (extremely large or pathological DXF) | low | accept | Worker boundary already prevents main thread hang; structural DXFs are KB-low MB range per project research; adding a parse timeout is not worth the complexity for Phase 1 |
| T-01-03 | Tampering | TEXT/MTEXT entity content and layer names rendered in DOM | medium | mitigate | All DXF text values rendered as React JSX children (automatic escaping); never use dangerouslySetInnerHTML in any DXF text rendering path; enforced via must_haves.prohibitions |
| T-01-SC | Tampering | npm package installs | high | mitigate | Package legitimacy gate with blocking-human checkpoint before any npm install; five SUS-flagged packages verified by human before proceeding |
</threat_model>
