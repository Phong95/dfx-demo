    ENTITY TAG RANGES (entityTagRanges.ts, new file) per RESEARCH Pattern 4 and D-10:

    Create a module that exports a buildEntityTagRanges function accepting the raw DXF text string and returning an array of EntityRange objects, each with startOffset (number), endOffset (number), and type (string). This scanner walks the raw text preserving character offsets (NEVER split the text into a line array and rejoin it later — that loses the original line-ending bytes per RESEARCH Pitfall 2). Use a regex tokenizer that matches each line including its terminator to track character positions.

    Define the SUPPORTED_TYPES set matching dxf-parser's registered entity handlers exactly: 3DFACE, ARC, ATTDEF, CIRCLE, DIMENSION, ELLIPSE, INSERT, LINE, LWPOLYLINE, MTEXT, POINT, POLYLINE, SOLID, SPLINE, TEXT. NOTE: VERTEX is NOT in this set (it is consumed internally by dxf-parser's polyline handler, not registered as a top-level entity).

    The scanner tracks whether it is inside the ENTITIES section (entered via a (0, SECTION) followed by (2, ENTITIES) pair, exited on (0, ENDSEC)). Inside ENTITIES, on each (0, TYPE) group-code pair where TYPE is not VERTEX and not SEQEND: close and push any current EntityRange (setting its endOffset to the current group's start offset), then open a new EntityRange with the current group's start offset and the TYPE value. VERTEX and SEQEND markers are continuation lines of the preceding POLYLINE entity range and must NOT start a new range — this is the key polyline-awareness that RESEARCH Pattern 4 specifies.

    After walking the entire text, close any remaining open range. Then filter the output array to only include ranges whose type is in SUPPORTED_TYPES. The resulting filtered array is index-aligned 1:1 with dxfData.entities because dxf-parser pushes exactly one entry per registered top-level handler in file order (with POLYLINE consuming its VERTEX/SEQEND internally per RESEARCH verification).

    EXPORT DXF (exportDxf.ts, new file) per RESEARCH Patterns 5 and 6, D-10, D-11, D-12:

    Export three functions: filterDxfText, validateExport, and saveDxf.

    filterDxfText accepts the original raw DXF text string, the EntityRange array from buildEntityTagRanges, and a Set of deleted entity indices. It builds the output by iterating through ranges: for each range whose index is in the deleted set, append everything from the current cursor position up to the range start offset (preserving untouched content), then advance the cursor past the range end offset (skipping the deleted entity's raw text). For ranges not in the deleted set, do nothing (their text remains in the output naturally). After all ranges, append the remainder from the cursor to the end of the string. This produces a cleaned string that is byte-for-byte identical to the original except with deleted entity blocks surgically removed. Hidden entities (in hiddenEntityIndices but not in deletedEntityIndices) are NOT filtered out per D-11 — hiding is view-only.

    validateExport accepts the filtered text string and the expected entity count (original entity count minus deleted count). It instantiates a new DxfParser (import DxfParser from dxf-parser), calls parseSync on the filtered text inside a try-catch, and returns true only if the parsed result is not null and the result entities length equals the expected count. Any thrown error returns false per RESEARCH Pattern 5.

    saveDxf accepts the text string and a suggested filename string. It uses feature detection to check for showSaveFilePicker in window: if available, call it with suggestedName and a types array containing one entry with description DXF Drawing and accept mapping application/dxf to the .dxf extension. Write the text via createWritable then write then close. If showSaveFilePicker is not available, fall back to creating a Blob with type application/dxf, creating an object URL, creating a temporary anchor element with the download attribute set to the suggested name, clicking it programmatically, and revoking the object URL. CRITICAL per RESEARCH Pitfall 6: wrap the showSaveFilePicker call in a try-catch that checks error.name equals AbortError and treats that as a silent no-op (user cancelled the dialog), NOT as an export failure.

    RAW TAG SCAN FIX (rawTagScan.ts) per RESEARCH Pitfall 1:
